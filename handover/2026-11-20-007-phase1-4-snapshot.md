# Session 007 — Phase 1.4: snapshot export/import

**ADR 0002 accepted** (`docs/decisions/0002-snapshot-format.md`): one
gzip+tar file (not a restic repo) — `manifest.json` first, then
`stack/…` and `volumes/<name>/…`, per-file sha256 in PAX records.
Volumes are captured/restored via **helper-container exec sessions**
(sleeper container with the volume at `/vol`, then exec the tar
command). Helper image: `alpine:3.20` (busybox tar), pulled if missing.

Implemented (Layer 1 green, `scripts/test.sh --fast`: 4/0):

- `internal/snapshot` — `Export` (streams), `Restore` (verifies
  checksums + contained paths, refuses existing stack dir/volume),
  `dockerBackend` (daemon client incl. `RunHelper`)
- endpoints: `POST /stacks/{name}/export`,
  `POST /stacks/{name}/import` (registered on the peer mux)
- volume ownership: accepted by compose label **or** `<stack>_`
  name prefix (restore-created volumes have no labels)

**Live proof** (home box, real daemon): ran a test compose stack with
a named volume (data written by the container), exported, tore
everything down, imported into a fresh peer state dir — compose file
and volume data intact on both sides.

**Bugs found live (both Docker attach gotchas):**
1. `ContainerAttach` must happen **before** `ContainerStart`, or stdout
   buffers deadlock the helper. Worse: attach-stdin of a
   not-yet-started container **silently drops client stdin** (0 bytes
   delivered, no error). Fix: sleeper container + `ContainerExecAttach`
   on the live container.
2. Exec-attach stdin is **raw** (unframed); stdout/stderr are framed
   (demux via `stdcopy.StdCopy`). Framed stdin leaked its 8-byte
   headers into the payload (10008 vs 10000 bytes).

**Watch out:** `mux.Handle("/", …)` twice panics at startup — snapshot
routes are registered directly on the peer mux with method patterns,
not as a nested mux.
