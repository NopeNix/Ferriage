# Session 008 — Phase 1.4 finished (007 left it uncommitted)

**Phase 1.4 is done and committed.** Found session 007's work uncommitted
(ADR 0002 + `internal/snapshot` + one-line `main.go` wiring). It
compiled and unit-tested green but had two live problems, both fixed
here:

1. **Lint red**: `ImageInspectWithRaw` deprecated → `ImageInspect`
   (one call). `--fast` now 4/0.
2. **Restore broken live** (the real catch): volume data travelled
   through the helper container's attach stdin (`tar -xvf -`). On this
   stack that path delivers **zero bytes** — plain `cat` gets 0
   bytes, tar says "short read", import fails 500. 007's sleeper +
   exec-attach rewrite didn't actually fix it (stdin still dropped).
   Fix: volume data never touches the attach stream. Capture/restore
   use the daemon's copy APIs (`CopyFromContainer` /
   `CopyToContainer`) through a sleeper container with the volume at
   `/vol`; the daemon tars the mountpoint itself. `RunHelper`/`run`
   (the exec-attach machinery) and the `Backend.RunHelper` interface
   method are deleted — dead code after the move. Copy entries come
   rooted at `vol/…`; `copyTarRebase` strips the root to
   volume-relative paths.

**Live proof** (home box, real daemon, fresh rebuild):
`docker compose up` a test stack with a named volume → `POST
/stacks/demo/export` → manifest correct, volume file present →
`down -v` + delete state dir → `POST /stacks/demo/import` → 200 →
`up` → volume data `hello-volume` intact. Probes cleaned up
(containers, volumes, `/tmp` dirs, temp binaries).

**Lesson worth keeping:** attach stdin is not a data channel on this
stack. Copy APIs are the first-class way to move volume data in and
out; anything else needs a live byte-count probe before it's trusted.
