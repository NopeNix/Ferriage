# Session 019 — Phase 3 (8/8): restic backup/restore

**Full routine `60 passed, 0 failed`** (was 53/0; +7 backup
checks). ADR 0011 + `internal/backup`: restic **CLI-in-peer**
(same shell-out precedent as `docker compose` in deploy — not a
sidecar, not a Go binding). Peer `GET /backup` (repo status +
snapshot history, password **never** exposed — only
`password_set`, ADR 0007 discipline), `POST /backup/run`
(one stack or the whole node), `POST /backup/restore`
(health-gated deploy), `POST /backup/forget` (retention,
`FERRIAGE_BACKUP_KEEP`, default 7). Repo at
`.ferriage/restic-repo` (never synced), password from
`FERRIAGE_RESTIC_PASSWORD` or `FERRIAGE_RESTIC_PASSWORD_FILE`.
Volumes captured via the daemon copy APIs into a temp tree
(the ADR 0002 payload, incremental + deduplicated in the repo),
restores re-populate fresh volumes. CLI `ferriage backup
[run|list|restore|forget]`, 4 MCP tools (`list_backups`,
`run_backup`, `restore_backup`, `forget_backups` — 15→19),
`BackupStatus` UI card, Shoutrrr `backup.ok`/`backup.failed`,
audit `backup.run`/`backup.restore`/`backup.forget`. Peer image
ships Alpine's `restic` apk (0.16.4); `deploy/docker-compose.yml`
gains the three env vars.

Live proof on the home box (restic 0.18.1, peer :18094): stack
backup → snapshot `088d1710`, second run same data deduped
(`data_blobs: 0`), node backup, `backup forget` kept last 7,
restore after `down -v` + state-dir removal → **healthy=true,
volume marker `backup-marker-v1` back, container healthy** in
the daemon; audit shows `backup.run`/`backup.restore`/
`backup.forget`; MCP `tools/list` 19 tools. Two live-found
bugs fixed: restic's `summary` is an **object** (not bool) so
`snapshots --json` failed to parse — over-tolerant
`json.RawMessage` now; and restore nested under the staged
tmpdir path (`<target>/tmp/ferriage-backup-*/stack`), so
the payload walk finds the `ferriage-backup-*` dir at any
depth (unit-tested).
