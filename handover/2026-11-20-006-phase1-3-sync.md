# Session 006 — Phase 1.3: state-sync ADR + mesh sync

**ADR 0001 accepted** (`docs/decisions/0001-state-sync.md`): manifest-based
file sync (not git-style) — sha256 manifest + blob fetch, LWW per file
by `(updated_at, peer_id)`, durable tombstone ledger, ed25519 peer
identity persisted outside the synced tree (`.ferriage/`), transport
split (Phase 1 = plain HTTP to `FERRIAGE_PEER` list; Iroh/QUIC swaps
the carrier later without protocol migration).

Implemented (all Layer 1 green, `scripts/test.sh --fast`: 4/0):

- `internal/identity` — ed25519 keypair, `LoadOrCreate`, 0600 perms,
  `peer_id` = hex(pubkey)
- `internal/sync` — manifest walk (skips `.ferriage`, symlinks),
  `ValidatePath`/`Resolve` (no `..`, no escape, symlink containment),
  `AtomicWrite` (temp+verify+rename), ledger (`sync-ledger.json`),
  tombstone rules (brand-new peer never deletes; touched-since-pull
  files kept; honored deletes never healed back)
- endpoints: `GET /sync/manifest`, `GET /sync/blob?path=`,
  `GET /peer`
- `cmd/peer` wiring: `FERRIAGE_PEER` (comma list), `FERRIAGE_SYNC_INTERVAL`
  (default 30s), single sync goroutine owns the ledger

**Live proof** (home box, 2 peer processes): write on A → B; edit on B
→ A (LWW); delete on B → honored on A; `.ferriage/` never synced.
Probes cleaned up.

**Bug found live**: `main.go` ran the ticker `Loop` *and* an extra
first-pull goroutine concurrently over one ledger map → delete
propagation flaked. Fixed: `Loop` pulls immediately on start, one owner.
