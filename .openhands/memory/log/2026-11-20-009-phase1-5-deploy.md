# Session 009 — deploy shells out to `docker compose`; compose `--wait` lies

Phase 1.5 deploy: `docker compose up -d` via CLI + Engine-API health
gate. Two live lessons:

- **`docker compose up --wait` is the wrong gate.** It exits 1 with
  "container X is unhealthy" — same verdict as our gate, but the
  per-service state we want to report is buried in its exit code and
  stderr. Plain `up -d` + polling `ContainerInspect.Health.Status`
  gives structured state (`starting`/`healthy`/`unhealthy`/`none`)
  and lets us return 502 with exactly which service is sick. Our
  own gate is also the thing that can keep watching past the point
  compose gives up.
- **Compose health semantics:** a container with no healthcheck
  reports Health `none`; treat it as healthy once `running`.
  `starting` and `unhealthy` must keep polling — `unhealthy` can
  flip back (daemon retries), so a one-shot "unhealthy = fail now"
  is wrong; only the timeout is final.

Decision recorded in `handover/2026-11-20-009-phase1-5-deploy.md`:
no compose-go for the milestone; CLI + Engine API. Reversible.
