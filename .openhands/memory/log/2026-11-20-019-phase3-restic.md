# Session 019 — Phase 3 (8/8): restic backup/restore

- ADR 0011: restic CLI-in-peer (docker-compose shell-out
  precedent), repo `.ferriage/restic-repo`, password
  `FERRIAGE_RESTIC_PASSWORD` / `_FILE` env-only, `GET /backup`
  exposes only `password_set`. Peer image: Alpine `restic` apk.
- restic `snapshots --json`: `summary` is an **object**
  with stats, not a bool — parse with `json.RawMessage`
  (over-tolerant: image pins Alpine's version, host may have
  0.18).
- restic records staged paths by absolute tmpdir: restore
  lands at `<target>/tmp/ferriage-backup-*/stack`. Payload
  detection must walk for the `ferriage-backup-*` dir at any
  depth, not check the restore root.
- Dedup proof: second backup of identical data reports
  `data_blobs: 0` — the incremental engine is doing its job.
  Node backup = per-stack staged subtrees under one tmpdir.
- Full routine 60/0, live restore → healthy=true with volume
  marker intact. Phase 3 complete; Phase 4 (tag/release/image)
  is user-gated.
