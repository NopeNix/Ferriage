# Session 020 — Multi-peer E2E + ADR 0012 (origin-gated deletes)

- 3-peer tests exposed 4 real sync defects, each caught by
  the next test layer (Go choreographed tests masked the
  async ones; the container mesh caught the rest):
  1. Fan-in delete: Apply deleted files absent from ANY
     source's manifest. Fix: origin-gated deletes — a
     delete fires only when the ORIGIN peer drops the path.
     Entry carries origin_id (ledger-pinned, served in
     manifest, additive wire). Two failed designs: unanimity
     votes (deadlock once all hold copies), last-server
     lineage (mtime drift flips it).
  2. Tombstone stored GeneratedAt; now keeps the deleted
     entry's UpdatedAt/OriginID/SHA (content-aware: same
     SHA honored-dead, newer write revives).
  3. SyncOnce aborted on first dead peer; now tolerant,
     errors only if ALL peers fail.
  4. Operator `rm` healed back: origin peer re-pulled its
     own delete from holders. Fix: local-delete scan at
     top of Apply tombstones vanished ledger-known paths
     before pulling; refresh records provenance for ALL
     local paths (incl. originator's own writes).
- pullOne now preserves origin mtime (Chtimes) so identical
  content builds identical manifests — kills pull-order
  mtime drift as an LWW tiebreak source.
- Wire: SyncEntry gains optional origin_id (openapi.go +
  drift test mirror + regen web/types.ts via live peer).
  Empty origin = serving peer (old rule). No migration.
- Layer 2.5 in test.sh: 3 peer CONTAINERS, full mesh
  (each pulls other two), ports 18100+ dynamic scan +
  /peer distinct-identity check. The dynamic ports exist
  because a stale dev peer squatted 18084 and silently
  answered healthz for a container that never bound
  (host networking) — poisoning the first run. Ports
  18080/81/82 are also squattable; layer 2/3 rely on the
  operator killing dev peers, layer 2.5 no longer does.
- Full routine 67/0. 8 new Go tests (mesh_test.go),
  7 mesh checks in layer 2.5. ADR 0012 amends 0001.
