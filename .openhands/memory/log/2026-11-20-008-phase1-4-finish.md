# Session 008 — attach stdin delivers 0 bytes; use copy APIs

Docker attach stdin (and exec-attach stdin) on this stack silently
delivers **zero bytes** to the container process — no error, `cat`
just gets EOF, tar reports "short read". Verified with raw hijacked-
conn writes, `io.Copy`, delayed writes, TTY on/off: all 0 bytes.
`weston`-style attach-into-stdin data channels are dead here.

What works: the daemon's first-class copy APIs through a throwaway
sleeper container with the volume mounted — `CopyFromContainer`
(capture) / `CopyToContainer` (restore). The daemon tars the
mountpoint itself; entries come rooted at the copied dir's base name
(`vol/greeting.txt` for `/vol`), so rebase by stripping the first
segment. This also covers remote `DOCKER_HOST` daemons.

Related gotchas on this stack (all live-verified):
- `golangci-lint` flags deprecated `ImageInspectWithRaw` —
  `ImageInspect` is the replacement.
- Untracked new packages don't show in `git diff` — `git status`
  is the source of truth for "what's uncommitted".
