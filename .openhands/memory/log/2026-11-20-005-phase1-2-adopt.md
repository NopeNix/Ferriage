# Session 005 — Phase 1.2: state dir + adopt by labels + GET /stacks

Packages added: `internal/state` (stacks dir on disk, ensure+list),
`internal/adopt` (groups running containers by
`com.docker.compose.project` label; skips unlabeled, oneoff, and
zero-container projects), `internal/stacks` (GET /stacks → JSON,
502 on daemon error). `cmd/peer` creates the state dir at boot
(`FERRIAGE_STATE_DIR`, default `./stacks`) and serves `/stacks`
alongside `/healthz`.

Proved live on home box: `/stacks` returned `owui-tooling` (compose
labels: project, service, config file, working dir) right after
`docker compose ps`. No Dockerfile/compose for Ferriage itself yet
(1.6); no merge/push/tag — user-gated per AGENTS.md §6.

## Gotchas (expensive to rediscover)

- **docker/docker v28.5.2 pulls transitive deps requiring Go 1.26**
  (go-winio, x/sys, x/time, otel). Host Go is 1.25.5. Worked around by
  pinning the whole chain down: `go 1.25.0` in go.mod + otel v1.37.0/
  otelhttp v0.62.0, x/time v0.15.0, go-winio v0.6.2 (drop + get needs
  GOTOOLCHAIN=local to avoid the 1.26 toolchain auto-switch).
  `golangci-lint` (built with go1.25) then passes. If deps get
  bumped again and lint reports "Go version too low", re-pin.
- **`.gitignore` `stacks/` also matched `internal/stacks/`** (Go
  package dir) — fixed to `/stacks/` (anchored). The same rule lived
  in `.git/info/exclude` (local-only); fixed there too. Local
  untracked files can be silently invisible: check with
  `git check-ignore` when a new file doesn't show in status.
- When seeding temp gitignore probes, remember `stacks/` is ignored
  at repo root — create the directory, test ignore, then clean up.
