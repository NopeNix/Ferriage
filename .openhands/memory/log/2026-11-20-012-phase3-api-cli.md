# Phase 3 (item 1): typed API + CLI + stack detail

- **Typed API in three layers**: Go structs (`internal/api`)
  → OpenAPI 3.1 doc (`/openapi.json`, hand-written, no codegen
  dep) → generated TS types. The drift guard is
  `openapi_test.go` (reflection over JSON tags vs the doc's
  `properties`); it caught nothing at first because the structs
  were written from the doc — that's the point.
- **Handlers marshal `internal/api` types, never maps**; the one
  structurally-duplicated type (`adopt.Stack` ↔ `api.Stack`)
  is mapped field-by-field, and the drift test compares their
  field sets too.
- **CLI shares the Go types** (`cmd/ferriage` imports
  `internal/api`) so a rename breaks CLI, web-gen, and tests
  together. `--json` pretty-prints (2-space): shell greps need
  `"name": "` with the space.
- **Dev peer adopts host containers** — screenshots/dev stacks
  show whatever compose projects run on the box (owui-tooling
  here). Ask before judging a "phantom" stack in dev.
- Full routine `29/0` incl. new layer 1.5 (CLI e2e, 10 checks)
  and `npm run gen:check` in the same layer.
