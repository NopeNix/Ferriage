# Session 006 — Phase 1.3: state-sync

- **ADR 0001**: manifest+blob file-sync (not git-style); LWW per file by
  `(updated_at, peer_id)`, sha tie-break; Phase 1 carrier = plain HTTP
  `FERRIAGE_PEER` list, Iroh later swaps carrier only.
- **Identity/ledger live OUTSIDE the synced tree**: `<stateDir>/.ferriage/`
  (identity.json 0600 + sync-ledger.json). Never walked by manifest.
- **Tombstone rules**: brand-new peer (empty ledger) never deletes;
  file edited since last pull (mtime > ledger baseline) is kept;
  honored deletes are never healed back from a stale peer.
- **Pulled files**: ledger baseline must be the *local* file's mtime
  read back from disk — the remote `updated_at` is a different clock
  and would suppress deletes forever.
- **Go test cache gotcha**: after editing code, a re-run of the same
  `go test` can replay a *cached failure* (or pass). Use `-count=1`
  when verifying a fix; `scripts/test.sh --fast` runs `go test ./...`
  without it — rerun once if a failure looks stale.
- **Bug caught live**: two goroutines (ticker loop + first-pull) sharing
  one ledger map = data race that broke delete propagation. Single
  owner now; the live two-process proof exercised it.
